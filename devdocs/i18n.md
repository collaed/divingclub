## i18n.md — Internationalization & Translation

## Overview

15 locales supported. All user-facing strings use `__()`. Articles are auto-translated via Google Translate API. User's preferred language stored in profile and respected throughout the app.

## Supported Locales (15)

`en`, `fr`, `de`, `lb` (Luxembourgish), `pt` (European Portuguese), `it`, `nl`, `es`, `pl`, `hu`, `ro`, `el`, `et`, `sk`, `fi`

## Architecture

### Static Strings (UI labels, buttons, messages)
- Stored in `lang/{locale}/` directories (PHP arrays) and `lang/{locale}.json` (JSON)
- Accessed via `__('key')` or `@lang('key')` in Blade
- French content in seeds/fixtures, English in code

### Dynamic Content (Articles)
- Auto-translated via `ArticleTranslationService` using Google Translate
- Stored in `article_translations` table (one row per article×locale)
- Displayed in tabbed UI matching user's preferred locale

## User Language Preference

| Storage | Field | Purpose |
|---------|-------|---------|
| `users.preferred_locale` | varchar(5) | Primary locale preference |
| `member_details.preferred_language` | varchar(5) | Extended profile setting |
| Browser `Accept-Language` header | — | Fallback for guests |

### Resolution Order
1. User's `preferred_locale` (if authenticated)
2. Session locale (if previously set)
3. Browser `Accept-Language` header
4. App default (`config('app.locale')` = `en`)

### Middleware: `SetLocale`
Applied to all web routes. Sets `app()->setLocale()` based on the resolution order above.

## Google Translate Integration

### API Endpoint
Uses the free `gtx` endpoint: `https://translate.googleapis.com/translate_a/single`

### Parameters
- `client=gtx`, `sl={from}`, `tl={to}`, `dt=t`, `q={text}`

### Portuguese Mapping
- Internal locale: `pt`
- API target: `pt-PT` (European Portuguese, not Brazilian)

### Chunking
Texts >4500 chars are split on paragraph boundaries (`</p>`, `</h1-6>`, `<br>`) and translated in chunks with 300ms delay between requests.

### Placeholder Preservation
Template variables (`{{ ... }}`) and media tags (`<img>`, `<video>`, `<iframe>`) are replaced with tokens (`⟦TK0⟧`) before translation and restored after.

## Translation Quality

### Staleness Detection
- `source_hash` (xxh3) stored on each translation
- When article is updated, `ArticleTranslationService::markStaleIfChanged()` marks translations as `stale = true`
- `ProcessTranslations` job (hourly) re-translates stale entries

### Word Count Validation
- Source and translated word counts stored
- `hasPlausibleWordCount()` method on ArticleTranslation flags suspicious ratios
- Flagged translations get `flagged_at` + `flag_reason` for bureau review

### Retry Logic
- Failed translations increment `retries` counter
- Capped at configurable max retries before giving up

## Scheduled Job: `ProcessTranslations`

Runs **hourly**. Finds articles with stale or missing translations and processes them. Heartbeat recorded in `schedule_heartbeats`.

## Convention Rules

- All user-facing strings wrapped in `__()` — titles, buttons, placeholders, flash messages
- French content in database seeds and fixtures
- English in source code comments and variable names
- Never hardcode display text in controllers or services
